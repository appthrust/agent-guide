# 単一の書き手、所有者の入力、誠実なクリーンアップ

## 過去の観察

Auth 環境の廃止では、server-side apply でフィールドを省略しても、古いマネージャーがまだ所有しているエントリは削除されないことが明らかになりました。そのため、新しいイメージが稼働していても、望ましい状態が正確に配送されたことにはなりませんでした。恒久的な修正は、所有者側のマイグレーションロジックに置くべきものであり、ID と並行性のチェック、および無関係なフィールドの保持を伴うものでした。

## 再利用可能なルール

宣言された意図と、コントローラーが所有するその投影は、互いに置き換え可能な書き込み面ではありません。投影を変更すると、上書きされたり、稼働中のコントローラーと競合したり、所有権を気付かないうちに広げたりする可能性があります。何かを変更する前に、現在の所有者とサポートされている入力を特定してください。

書き手のリースは衝突を調整するものであり、認可を生み出すものではありません。共有された対象に書き込む前に、対象、権限、唯一の書き手、想定される差分、観察の境界を明示してください。タスクが PMC や Gateway の作業に及ぶ場合は、運用者の権限を別途取得してください。このガイドがその権限を付与することはできません。

## エージェントの対応

変更前の状態を記録し、認可された範囲の狭い所有者の入力を使い、直後に読み戻して、対象外の状態を比較してください。失敗した状態の証拠は、それが問題の説明に役立つ間は保持してください。よりきれいな結果を得るためだけに環境を削除・再作成したり、自分のクリーンアップ中に他のワーカーのリソースを削除したりしないでください。

クローズアウト時には、何を削除したか、何を意図的に残したか、どの不在確認が実際に可能だったかを明記してください。Project や API のレコードを削除しても、すべてのクラスターやプロバイダーのリソースが消えたことの証明にはなりません。タスクが所有する一時的な付与は取り消し、機密情報は削除し、調整用のリースはその所有者を通じて解放してください。

このガイドのどの教訓も、managed fields の操作、コントローラーの迂回、稼働中のクラスターの操作を認可するものではありません。
